# Universal Config Engine 1.2.0-rc.1

Minor release candidate for safe inspection, configuration comparison and CI
change policies. All five packages use `1.2.0-rc.1` and npm `next`; npm `latest`
remains on stable `1.1.2` until candidate verification and stable promotion.

## Added

- Core `buildConfigInspection` and `uce explain --values` / `--path` show bounded
  public scalar previews, precise typed paths and retained source, override,
  location, coercion and validation history. Containers never embed raw contents.
- Core `buildConfigDiff` and `uce diff --config before.json --against after.json`
  compare complete values and source metadata. Secrets remain hidden; explicit
  `--detect-secret-changes` compares them only in memory and emits change metadata.
- Core `checkConfigChanges` and `uce diff --policy policy.json` support bounded
  `forbid-changes`, `require-path` and `allowed-sources` rules. Invalid inputs and
  resource-limit failures cannot produce a successful policy result.
- Inspection and comparison inherit secret policies from both compared versions,
  participating source history and atomic arrays, and enforce entry/byte budgets.

## Fixed

- Await real Zod asynchronous parsing, refinements and transforms; rejected
  callbacks reach the sanitized validation boundary without unhandled rejections.
  Direct adapter consumers must await `validate` results.
- Share finite issue-detail validation across loaders and validators.
- Bound retained source diagnostics without copying discarded issue arrays,
  preserving source rejection for errors beyond the retained prefix.

## Compatibility and Verification

Existing default explain/validate envelopes remain schema `0.2`. New opt-in
reports use `inspection-1`, `diff-1` and `change-check-1`. Existing exports and
`CliCommand` retain their contracts. Node.js >=24 and ESM remain required.
No new runtime dependencies or hosted workflows are introduced.

Install all packages at the same exact candidate version. See
[the inspection and comparison guide](../cli/inspection-and-diff.md) and
[ADR 0017](../adr/0017-inspection-diff-and-change-policy.md).

Stable promotion requires exact-commit CI, CodeQL, minimum/current Node.js and
Linux/Windows packed-consumer checks, release dry-run, complete 5/5 publication
manifests, npm integrity/provenance and installation from the public registry.
If a regression is found, consumers can pin stable `1.1.2`; published versions and
tags remain immutable.
