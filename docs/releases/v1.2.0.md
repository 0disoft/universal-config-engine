# Universal Config Engine 1.2.0

Release date: 2026-10-21.

Minor release for explaining effective settings and checking changes before
deployment. All five packages use `1.2.0` and npm `latest`. This promotes verified
candidate `1.2.0-rc.1` at `5377ad94fce6ee416922ff7f6925a41b5db0b6fd` without
runtime, public declaration, dependency, package README, fixture or runner changes.

## Added

- `buildConfigInspection`, `uce explain --values` and typed `--path` queries:
  bounded public scalar previews plus source, override, location, coercion and
  validation history, with secret containers kept opaque.
- `buildConfigDiff` and `uce diff --config before.json --against after.json`:
  complete-value and source-aware comparison. Secret comparisons are skipped by
  default; explicit `--detect-secret-changes` reports only change metadata.
- `checkConfigChanges` and `uce diff --policy policy.json`: bounded rules for
  forbidden changes, required paths and allowed winning sources. Failed or
  incomplete comparisons cannot pass CI policies.
- Secret policies apply across both compared versions, source history and atomic
  arrays. Entry, path, preview and UTF-8 byte limits bound inspection work/output.

## Fixed

- Await asynchronous Zod parsing and contain rejected callbacks through the
  sanitized pipeline boundary. Direct adapter consumers must await `validate`.
- Consistently reject non-finite loader/validator issue details.
- Avoid copying discarded source diagnostics while preserving late error rejection.

## Compatibility

Default explain/validate output remains schema `0.2`; opt-in reports use
`inspection-1`, `diff-1` and `change-check-1`. Existing exports and `CliCommand`
retain their contracts. Node.js >=24 and ESM remain required. No new runtime
dependencies or hosted workflows are introduced. Keep all packages aligned:

```sh
npm install @0disoft/universal-config-engine-core@1.2.0 @0disoft/universal-config-engine-node@1.2.0
npm install --save-dev @0disoft/universal-config-engine-cli@1.2.0
```

See [the guide](../cli/inspection-and-diff.md) and [ADR 0017](../adr/0017-inspection-diff-and-change-policy.md).
Optional validator packages are `@0disoft/universal-config-engine-validator-ajv`
and `@0disoft/universal-config-engine-validator-zod`. If a regression is found,
consumers can pin stable `1.1.2`; published versions and tags remain immutable.

Release gates require exact-commit CI, CodeQL, minimum/current Node.js and
Linux/Windows packed consumers, release dry-run, complete candidate publication,
registry installation and npm provenance/integrity. Assets retain publication
manifests, independent verification receipts and a commit-bound SPDX SBOM.
