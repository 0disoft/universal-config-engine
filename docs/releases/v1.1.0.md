# Universal Config Engine 1.1.0

Release date: 2026-10-20.

This compatible minor release promotes `1.1.0-rc.1` from
`5f625a0535d0196145bcc86a5a0c4633e654c023` without runtime, dependency, public
declaration or package README changes. All five packages share version `1.1.0`
and use npm `latest`.

## Improvements

- Optional Node JSON-loader `maxLocationBytes` (default 4 MiB) bounds location
  metadata independently of parsed config. Exceeding it omits optional locations
  with a warning; it does not reject values or cap the total JavaScript heap.
- Deep JSON reaches configured structural limits without recursive parser,
  cloning, path-index, location-collection or validator-freezing stack failures.
- JSON mapping/coercion rejects non-finite numbers and unsafe keys consistently.
- Loading preflight and diagnostic-overflow failures cannot become successful
  pipeline results. Scalar leaves also respect depth/path limits.
- Reusing validator, coercion or mapping path arrays cannot rewrite retained
  diagnostics/provenance or change their secret-path redaction decisions.
- Explicit prototype-like override names remain usable; inherited values are
  ignored. Unicode argv assignments match split-form mappings, with one shared
  scan for strict diagnostics and values.
- Loader normalization bounds diagnostic copies while still validating malformed
  tail entries. File loading and resolved-path bookkeeping have clearer owners.

## Compatibility and Installation

No migration is required for existing valid `1.0.0` consumers. Node.js >=24, ESM,
CLI commands/exit codes and diagnostic schema `0.2` remain unchanged. Packages
remain aligned; install the same version for core, node, CLI and optional adapters.

```sh
npm install @0disoft/universal-config-engine-core@1.1.0 @0disoft/universal-config-engine-node@1.1.0
npm install --save-dev @0disoft/universal-config-engine-cli@1.1.0
```

Optional adapters are `@0disoft/universal-config-engine-validator-ajv` and
`@0disoft/universal-config-engine-validator-zod`.

The release policy binds promotion to the candidate's exact commit and complete
publication evidence. Stable publication requires its own CI, CodeQL, minimum and
current Node.js checks, Linux/Windows packed consumers, release dry-run and registry
installation checks. Release assets include publication manifests and the SPDX
SBOM; npm provenance and integrity bind published tarballs to the release commit.
