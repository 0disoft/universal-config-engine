# Universal Config Engine 1.1.1

Release date: 2026-10-21.

This patch promotes `1.1.1-rc.1` from
`63e0504e7c3869e59dfefaa48cbdaba0e5d4b3cb` without runtime, public declaration,
dependency or package README changes. All five packages use `1.1.1` and npm `latest`.

## Fixed

`resolveConfig` rejects input exceeding `maxSources` before copying or sorting the
complete source list. Rejection reads only the bounded source-descriptor prefix;
priorities and values are not inspected. With 100,000 sources and a limit of 64,
a deterministic probe reduced source reads from 100,000 to 64 and priority reads
from 3,031,962 to zero. These operation counts are not a wall-clock latency promise.

## Compatibility

For rejected oversized inputs, `result.sources` now contains the first `maxSources`
descriptors in declaration order, replacing the globally priority-selected subset.
Consumers relying on that failure-only subset or order should adjust accordingly.
Normal source precedence, stable ties, merging and error codes remain unchanged.
No new exports or types. Node.js >=24, ESM, CLI commands/exit codes and diagnostic
schema `0.2` remain unchanged. Install all packages at the same version:

```sh
npm install @0disoft/universal-config-engine-core@1.1.1 @0disoft/universal-config-engine-node@1.1.1
npm install --save-dev @0disoft/universal-config-engine-cli@1.1.1
```

Optional adapters are `@0disoft/universal-config-engine-validator-ajv` and
`@0disoft/universal-config-engine-validator-zod`. Existing valid input needs no
migration. If a regression is found, consumers can pin the previous stable
`1.1.0` while a follow-up patch is prepared; published versions and tags are immutable.

Publication requires exact-commit CI, CodeQL, minimum/current Node.js checks,
Linux/Windows packed consumers, release dry-run, candidate evidence and registry
installation checks. Release assets retain publication manifests and a commit-bound
SPDX SBOM, alongside npm integrity and provenance evidence.
